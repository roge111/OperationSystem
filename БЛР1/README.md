### Структуры данных

Стурктуры данных создаются с помощю `typedef struct` и использются для хранения. По сути это как data-классы в Kotlin/Java. Но соедржат чисто поля, которые по умолчанию изменяемые

Пример:
```
typedef struct
{
    double user;
    double system;
    double wait;
    unsigned long context_switches;
} cpu_stats_t;
```

Присутсвуют следующие структуры данных:
- `cpu_stats_t` - структура для храненния многовенной статистики процессора. Имеются такие поля: `user` - доля времени cpu потраченное на пользовательские процессы, `system` - доля времени cpu потраченное на системные процессы, `wait` - доля времени cpu потраченное на ожидание, `context_switches` - количество переключений контекста.
- `monitoring_result_t` - структура для хранения средних результатов мониторинга. Имеет поля: `user_avg` - средняя доля времени cpu потраченное на пользовательские процессы, `system_avg` - средняя доля времени cpu потраченное на системные процессы, `wait_avg` - средняя доля времени cpu потраченное на ожидание, `context_switches_total` - общее количество переключений контекста, `context_switches_delta` - количество переключений контекста за последний интервал времени.

- `process_monitor_t` - структура для хранения информации о количестве параллельных процессов. Имеет поля: `volatile int monitor` - флаг активности мониторинаг, `int max_processes` - максимальное количество параллельных процессов.

### Функцци

#### process_monitor_thread

Функция для мониторинга количества параллельных процессов.

Испоьзует структуру `process_monitor_t` для хранения информации о количестве параллельных процессов. 
За измерение одно делает три проверки. 

Для сбора информации используются простые системные вызовы: `ps -e -o pid= | wc -l` и `pgrep -f '^\\.\\/loaders$'`

- `ps -e -o pid= | wc -l` - выводит общее число процессов. `ps`- показывает все процессы, `-e` - показывает процессы, не только запущенные в теримнале, `-o pid=` - выводит только pid процессов, `wc -l` - считает количество строк.
- `pgrep -f '^\\.\\/loaders$'` - выводит pid процесса, который запущен с именем `loaders`. `pgrep` - поиск процесса по имени, `-f` - поиск по имени файла, `'^\\./loaders$'` - ищет процессы, которые запущены с именем `loaders`

Логичка простая:
1) Находим общее число процессов.
2) Находим число процессов, которые запущены с именем `loaders`.
3) Находим разницу между двумя числами.

Эта разница и есть количество параллельных процессов, что запущены одновременно с программой и ее дочерними процессами.



#### get_cpu_stats_from_proc

Функция для мониторинга процессора.

Испоьзует структуру `cpu_stats_t` для хранения информации о процессоре.

Читает файл `/proc/stat` и считывает информацию о процессоре.

Логика следующая:
1) Открываем файл `/proc/stat`.
2) считываем в буфер (переменная `buffer`) информацию из файла.
3) Разбиваем строку из буфера. Примечание: вывод из файла будет выглядеть так: `cpu  12345 678 91011 121314 151617 1819 2021`. Порядой полей следующий: `user nice system idle iowait irq softirq`. Где:
    - `user` - это `%user`
    - `nice` - `%nice` (время, потраченные на процессы с приоритетом `nice` (пониженный приоритет). Процессы запускаеются через `nice` или с `nice`>0). По сути тоже относиться к пользовательскому процессу. 
    - `system` - `%sys`
    - `idle` - `%idle`
    - `iowait` - `%wait`
4) Скалдываем все параметры, чтобы получить общее время работы. И находим проценты на параметры `%user` (user + nice), `%sys` и `%wait`, умножая каждый на 100 и деля на общее время работы.
5) Вновь считваем информацию о статистике в буффера, пока не найдем нежную строку - с `ctxt`. Это информация по количеству переключений контекста. Хранится в виде: `ctxt 123456789`.
6) Считываем: `sscanf(buffer, "ctxt %lu", &ctxt)` и выходим из цикла `break`
7) Закрываем файл
8) Возвращаем результат.


#### cpu_monitoring

Функция для мониторинга процессора в отдельном потоке. Она использует функцию `get_cpu_stats_from_proc` для получения информации о процессоре в моменте. Делает несколько замеров (например, 5) скалдывая каждый параметр в общую сумму, а затем вычисляет среднее арфмитическое из всех успешных замеров. Количество успешных замеров храниться в `valid_samples`.


1) Выделяем память для результата `result`
```
monitoring_result_t* result = malloc(sizeof(monitoring_result_t));
if (!result) return NULL;
```
2) Объявляем необходмые переменные:
```
double total_user = 0.0, total_wait = 0.0, total_sys = 0.0;
int valid_samples = 0;
unsigned long first_context_switches = 0;
unsigned long last_context_switches = 0;
```
3) Делаем замеры и после каждого добавляем в общую сумму каждого параметра:
```

 for (int i = 0; i < 5; i++) { // Уменьшили до 5 замеров
    cpu_stats_t monitor = get_cpu_stats_from_proc();
    
    if (monitor.user >= 0 && monitor.system >= 0 && monitor.wait >= 0) {
        total_user += monitor.user;
        total_wait += monitor.wait;
        total_sys += monitor.system;
        valid_samples++;
        
        if (i == 0) {
            first_context_switches = monitor.context_switches;
        }
        last_context_switches = monitor.context_switches;
    }
    usleep(500000); // 0.5 секунды вместо 1
}
```
4) В последний замер и первый измеряем число переключений контектса. И потом находим разницу
5) находим среднее арфимитическое из всех успешных замеров:
```
result->user = total_user / valid_samples;
result->wait = total_wait / valid_samples;
result->system = total_sys / valid_samples;
result->context_switches = last_context_switches - first_context_switches;
```
6) Возвращаем результат:
```
return result;
```
